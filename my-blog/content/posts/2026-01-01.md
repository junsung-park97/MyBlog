# 용어 정리 (간단하게)

- **L4 로드밸런서**
  - 4계층에서 동작한다.
  - TCP/UDP Port번호를 보고 트래픽을 분산한다.
  - 빠르지만 HTTP내용을 모른다
- **L7 로드밸런서**
  - 7계층에서 동작한다.
  - HTTP URL, 헤더, 쿠키 등을 분석해서 더 똑똑하게 라우팅이 가능하다.
  - 조금 느리지만 유연하다.
- **L3 스위치**
  - 3계층 기능을 가진 스위치이다.
  - IP주소를 보고 라우팅이 가능하다.
  - 그래서 스위치와 라우터의 사이에서 중간역활을 수행한다.

# OSI 7계층이 왜 필요할까?

- 네트워크 통신은 매우 복잡하다. 데이터를 한번 전송하는데 신호변환부터, 에러 검출, 경로 설정, 신뢰성 보장, 데이터 형식 변환등 수 많은 작업이 필요하다.
- 이 모든것을 한번에 처리하기 매우 까다롭기때문에 7계층으로 나눠서 각자 역활을 분담하고, 책임 소재를 명확히 하기 위해 설계되었다.

# OSI 7계층의 동작 방식

- 각 계층은 독립적으로 동작하면서, 바로 위아래 계층하고만 통신한다.
- **이렇게 하면 특정 계층만 수정해도 다른 계층에 영향을 주지 않기 때문에**

### Layer 1 : 물리계층 (최하단)

- **역활**: 0과 1의 디지털 비트를 실제 물리적 신호로 변환해서 전송한다.

#### 구체적으로

- 전기신호
- 빛 신호
- 전파

### Layer 2 : 데이터링크 계층

- **역활**: 같은 로컬 네트워크(LAN) 안에서 직접 연결된 장비들끼리 데이터를 주고받습니다.

#### 핵심 개념

- **MAC 주소를 사용합니다**

> ### 용어
>
> **MAC이란?**
>
> - 네트워크 장비(네트워크 카드, NIC)마다 할당된 **고유한 물리적 주소**입니다. 제조사에서 하드웨어를 만들 때 부여하는 일종의 "제품 시리얼 번호"라고 생각하면 됩니다.

- **에러 검출** :
- 프레임 단위로 전송

#### 프로토콜

- 이더넷, WIFI

### Layer 3 : 네트워크 계층

#### 역활

- 서로 다른 네트워크 간에 데이터를 전달합니다. 출발지에서 목적지까지 최적의 경로를 찾아줍니다.

#### 핵심 개념

- **IP 주소 사용**
  - 예: 192.169.1.10 등등
- **라우팅 (경로 설정)**
- 패킷 단위로 전송

#### 프로토콜

- IP (Internet Protocol)
- ICMP (Ping 명령어)
- ARP (IP -> MAC 주소 변환)

> ### 실무 예시
>
> - **VCP**, **Subnet**이 바로 이 계층에서 동작한다.
> - 라우팅 테이블 설정
> - **NAT Gateway**도 해당 계층에서 동작
> - 서울서버에서 미국서버로 데이터를 보낼 때 여러 라우터를 거쳐가는 과정

### Layer 4 : 전송계층

#### 역활

- 종단 간(End-to-End) 신뢰성 있는 데이터 전송을 보장한다.

#### 핵심 개념

- **Port 번호 사용**
- 세그먼트 단위로 전송
- 흐름제어, 혼잡제어, 오류제어

#### 프로토콜

- TCP: 신뢰성이 보장, 연결 지향
- UDP: 빠르지만 신뢰성 보장이 안됨.

> ### 실무 예시
>
> - **로드밸런서의 L4**는 바로 이 계층에서 동작합니다. Port번호만 보고 트레픽을 분산합니다.
> - 웹 서버가 80번 포트를 보고 있다는 것은 4계층이라는 말이다.
> - Connection Pool 관리도 4계층과 관련되어있습니다.
> - `netstart` 명령어로 확인하는 TCP 연결 상태

### Layer 5 : 세션 계층

#### 역활

- 통신 세션을 설정, 유지, 종료 합니다.
- 해당 계층은 OSI 모델에는 있지만 TCP/IP 모델에서는 애플리케이션 계층에 흡수되어, 명확히 구분하지 않는 경우가 많습니다.

### Layer 6 : 표현 계층

#### 역활

- 사용자가 직접 사용하는 **네트워크 서비스**를 제공합니다.
- 해당 계층 또한 TCP/IP 모델에서는 애플리케이션 계층에 흡수되어있습니다.

### Layer 7 : 응용계층

#### 역활

- 사용자가 직접 사용하는 네트워크 서비스를 제공합니다.

#### 프로토콜

- HTTP/HTTPS(웹)
- DNS (도메인 이름 해석)
- SMTP (이메일)
- FTP (파일 전송)
- SSH (원격 접속)

> ### 실무 예시
>
> - 로드밸런서의 L7은 해당 계층에서 동작합니다. HTTP 헤더를 보고. `/api`는 API 서버로, `/images`는 CDN으로 라우팅하는 방식입니다.
> - REST API 설계
> - CORS 정책
> - 우리가 개발 하는 웹 어플리케이션

# 데이터 전송 과정 (캡슐화)

> - 사용자가 웹 브라우저에서 `https://example.com` 을 입력하면 데이터가 어떻게 전송될까?

## 송신측

#### Layer 7

- "GET / HTTP/1.1" 요청을 생성한다.

#### Layer 6 & 5

- 대부분 7계층에 통합됨.

#### Layer 4

- TCP 헤더 추가 (출발지 Port, 목적지 Port)
- 이것을 세그먼트라 부름

#### Layer 3

- IP 헤더 추가 (출발지 IP, 목적지 IP)
- 이것을 패킷이라부름

#### Layer 2

- 이더넷(Ethernet) 헤더 추가 (출발지 MAC, 목적지 MAC)
- 이제 이것을 프레임이라 부름

#### Layer 1

- 전기 / 빛 신호로 변환하여 전송

## 수신측

- 받은 쪽에서는 반대 순서대로 헤더를 벗겨내며 **역캡슐화(Decapsulation)** 합니다.
